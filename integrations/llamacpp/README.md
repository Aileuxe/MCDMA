# llama.cpp RPC over MCDMA

This experimental adapter carries llama.cpp RPC request and response frames through
`mcdma-rpcd` mailboxes. The interhost application payload uses MCDMA RDMA; TCP sockets
connect the adapter to the inference processes on each host's loopback interface.
There is no interhost TCP payload fallback.

**This adapter stages inference payload in host memory.** Upstream RPC serializes
tensor bytes, and this Python adapter copies them into and out of registered daemon
mailboxes. It does not allocate the model's tensors in shared GPU/RDMA memory, and
does not prove direct GPU tensor transfers. The separate CUDA/Vulkan GPU transfer
benchmark tests that property. Keep its results separate from measurements of this
adapter.

The adapter can carry the traffic generated by genuine tensor parallelism, but the
choice of parallel algorithm belongs to llama.cpp. Use `--split-mode tensor` for
TP=2, and verify that both devices execute shards of each supported layer.
`--split-mode layer` is pipeline parallelism. `--tensor-split` alone does not select
tensor parallelism. This directory currently contains transport tests, not evidence
that CUDA/Vulkan TP=2 inference has passed on hardware.

## Pinned protocol

Both peers must be built from llama.cpp revision
`4da6337767f973e2b4d0797e5b323d77d8565e4a`, which uses RPC protocol 7.0.0.
Run this check on each source tree before building:

```sh
python3 integrations/llamacpp/verify_source.py /path/to/llama.cpp
```

The check verifies HEAD and hashes of the three files defining the RPC protocol;
it does not prove that an existing binary was built from that checkout. Preserve
the compiler configuration and build provenance with results.

The authoritative protocol sources are
[ggml-rpc.cpp](https://github.com/ggml-org/llama.cpp/blob/4da6337767f973e2b4d0797e5b323d77d8565e4a/ggml/src/ggml-rpc/ggml-rpc.cpp),
[transport.h](https://github.com/ggml-org/llama.cpp/blob/4da6337767f973e2b4d0797e5b323d77d8565e4a/ggml/src/ggml-rpc/transport.h),
and [ggml-rpc.h](https://github.com/ggml-org/llama.cpp/blob/4da6337767f973e2b4d0797e5b323d77d8565e4a/ggml/include/ggml-rpc.h).
The adapter validates the 24-byte HELLO request and the server's exact version,
then clears HELLO transport capabilities in both directions. This prevents
llama.cpp from switching the local sockets to its own RDMA transport.

## Set up the processes

Use a dedicated, working [daemon link](../../docs/link-daemon.md), with one adapter
client on its connect end and one adapter service on its listen end. Both mailbox
halves may be 4 MiB; frames larger than either half are streamed as bounded chunks.
The processes need Python 3.10 or newer and this repository's `libmcdma-rpc` helper.
Neither adapter needs permission to open a verbs device.

Build llama.cpp with `-DGGML_RPC=ON -DGGML_RPC_RDMA=OFF` on both hosts, plus
`-DGGML_CUDA=ON` on the CUDA host or `-DGGML_VULKAN=ON` on the Vulkan host. Build the
`llama-bench`, `llama-cli`, and `ggml-rpc-server` targets. Use the same source revision
on both CPU architectures. The native RPC wire format is little endian and uses
64-bit pointers and sizes, as on aarch64 and x86-64 Linux.

For a Vulkan client with a remote CUDA device, arrange the MCDMA link with the CUDA
host as the listen end, then run these processes from the MCDMA repository:

```sh
# CUDA host: native inference server, restricted to loopback.
/path/to/llama.cpp/build/bin/ggml-rpc-server --host 127.0.0.1 --port 51001 --device CUDA0

# CUDA host: service attached to the dedicated MCDMA listen mailbox.
python3 integrations/llamacpp/mcdma_rpc_proxy.py service \
  --link inference-a --port 51001 \
  --library /path/to/libmcdma-rpc.so --metrics /tmp/mcdma-llama-service.json

# Vulkan host: local listener, using the MCDMA connect mailbox.
python3 integrations/llamacpp/mcdma_rpc_proxy.py client \
  --link inference-a --port 51002 \
  --library /path/to/libmcdma-rpc.so --metrics /tmp/mcdma-llama-client.json
```

The client only binds `127.0.0.1`, and the service only connects to `127.0.0.1`.
There is no remote hostname option. The daemon's existing control connection is
still required to establish its RDMA link; it is separate from these sockets.
Do not share this mailbox with another application. The adapter has an exclusive
client lock, and the daemon grants one service registration.

First list the inference devices through the proxy:

```sh
/path/to/llama.cpp/build/bin/llama-cli --rpc 127.0.0.1:51002 --list-devices
```

Use the actual returned device names. With `Vulkan0` and `RPC0`, a small TP=2
benchmark invocation for the pinned llama-bench is:

```sh
/path/to/llama.cpp/build/bin/llama-bench \
  -m /path/to/Qwen3-8B-Q8_0.gguf --rpc 127.0.0.1:51002 \
  -dev Vulkan0/RPC0 -sm tensor -ts 1/1 -ngl 99 \
  -fa on -ctk f16 -ctv f16 -p 512 -n 128 -r 5 -o json
```

The pinned **llama-bench uses slashes** inside its device and tensor-split lists;
llama-cli uses commas. Expand prompt lengths only after output correctness and
device placement pass. These are proposed commands, not recorded hardware results.
This upstream tensor mode remains experimental, especially for Vulkan and RPC.

## Failure and ordering rules

The mailbox protocol has OPEN, BEGIN, DATA, PULL, and CLOSE messages, with a random
session ID, a monotonic RPC request ID, and an exact chunk offset. It preserves
upstream's command order and knows which pinned RPC commands have no reply.
Every chunk is acknowledged before the next chunk is sent. Application memory use
is bounded by mailbox capacity even when a model tensor frame is much larger.

`--timeout` defaults to 300 seconds for an entire native RPC frame and for an idle
active session. Increase it explicitly if an individual graph computation or
model-load frame needs more time. `--max-frame-bytes` defaults to 64 GiB and can be
raised for larger individual frames; it is a validation limit, not a reservation.
Unexpected sequence or offset, protocol mismatch, link loss, changed daemon
generation, local socket failure, or a deadline causes a nonzero exit. The service
also closes the native RPC connection on exit, releasing that session's resources.

A healthy client disconnect closes its remote native session, after which another
local connection can begin. Failures are not retried and active work is never
replayed after reconnect. Restart the adapters after diagnosing an error; do not
use a failed run as benchmark evidence. The native inference server and the
MCDMA daemon remain separate processes owned by their operators.

## Metrics and verification

Both adapters emit JSON at startup, normal session close, and exit after failure
or interruption. `--metrics` also saves the latest aggregate JSON. No prompts,
tensor contents, or token outputs are logged.

`mcdma_request_payload_bytes` and `mcdma_reply_payload_bytes` count mailbox payload
bytes for completed exchanges, including this adapter's headers and acknowledgments.
They exclude Ethernet, RoCE, verbs, daemon notification words, and control-channel
overhead. Counters from the two endpoints describe the same exchanges and must not
be added together. A failed exchange can have moved bytes before failing, so these
counters are not total wire traffic in a failed run.

`rpc_request_frame_bytes` and `rpc_response_frame_bytes` count the native RPC
headers and bodies carried by the adapter. The corresponding `body_bytes` counters
exclude native framing but include RPC metadata, so they are not pure tensor-byte
counters. Per-command counts distinguish graph execution, tensor upload/download,
and setup. Every record explicitly marks host staging and
`direct_gpu_tensor_transfer: false`.

For trustworthy model results, preserve the model SHA-256, source/build pin,
GPU/backend selection, proxy JSON, daemon counters and errors, runtime output,
warmups, repetitions, and clock boundaries. Measure model-loading traffic separately
from inference traffic. Compare the same quantization and KV types with each host
alone, and validate generated output or logits before reporting throughput.

This transport does not itself implement disaggregated prefill/decode. That needs
a separate KV export/import integration, including positional metadata, cache
layout checks and evidence that the decoder does not repeat prefill. Serializing
state to host memory and transferring it through this adapter is host-staged KV
handoff, even though its interhost bytes use RDMA.

Run local tests without GPUs or an RDMA link:

```sh
python3 -m unittest discover -s integrations/llamacpp -p 'test_*.py' -v
```

The tests exercise large frames in both directions, byte-fragmented local sockets,
the no-response command set, HELLO capability stripping and version rejection,
chunk ordering, bounded deadlines, link loss and generation change. They establish
protocol behavior with fake mailbox transport, not hardware RDMA performance.

## Portable HTTP inference measurements

`measure_inference.py` records local monotonic first-token and completion times,
server timings, token outputs and raw SSE events from the pinned llama.cpp
`llama-server`. It does not start a model server, transfer state files, choose
tensor parallelism or establish that an inference transport used RDMA. Run it
against an already configured server and retain model hashes, source/build pin,
GPU placement and transport counters separately. Its default URL is
`http://127.0.0.1:8080`; set `--url` for an explicit different HTTP origin.

Create one private prompt artifact on a server using the intended tokenizer:

```sh
python3 integrations/llamacpp/measure_inference.py prompts \
  --output "$PRIVATE_RESULTS/prompts.json"
```

This tokenizes each component of a fixed, authored science prompt once and builds
exactly 512, 2048 and 8192 input tokens, recording the token IDs and their SHA-256.
The text uses the Qwen-style chat template of this measurement recipe. Reuse the
same artifact on both hosts; measurement actions never retokenize it. The reader
also accepts a simple JSON map from token-count strings to token-ID arrays, but
that older format lacks a stored digest to cross-check.

An uncached baseline for one input size is:

```sh
python3 integrations/llamacpp/measure_inference.py baseline \
  --prompts "$PRIVATE_RESULTS/prompts.json" --size 8192 \
  --repetitions 3 --n-predict 128 \
  --output "$PRIVATE_RESULTS/baseline-8192.json"
```

Repeat separately for `--size 512` and `--size 2048`, with new output names.
Requests use greedy settings, a fixed seed, `ignore_eos=true`, returned token IDs
and `cache_prompt=false`. A trial passes only when server timings report
`prompt_n` equal to the input size, `cache_n=0`, `predicted_n` equal to the requested
output count, and all generated token IDs were captured. No warmup is added
implicitly; perform and record any warmup separately. The default is three
repetitions and 128 output tokens, with each individual trial retained.

For a file-staged prefill/decode handoff, enable slot-state save/restore on both
servers, use matching model/tokenizer/KV formats, and reserve an exclusive slot
for these requests. The server resolves `--state-name` inside its configured
slot-save directory; it is a sanitized basename, not a path to the measurement
JSON or a file automatically copied to another machine:

```sh
# Producer HTTP server: measure prefill and save this slot's state.
python3 integrations/llamacpp/measure_inference.py prefill \
  --prompts "$PRIVATE_RESULTS/prompts.json" --size 8192 --repetitions 1 \
  --state-name trial-8192.state --output "$PRIVATE_RESULTS/prefill-8192.json"

# Transfer that exact state file separately, verifying its bytes, before decode.
# Decoder HTTP server: restore it and submit the same complete prompt token IDs.
python3 integrations/llamacpp/measure_inference.py decode \
  --prompts "$PRIVATE_RESULTS/prompts.json" --size 8192 --repetitions 1 \
  --state-name trial-8192.state --n-predict 128 \
  --output "$PRIVATE_RESULTS/decode-8192.json"
```

The pinned server samples **one token for a request with `n_predict=0`**, while the
saved KV state contains the input tokens. The prefill result records requested
count 0 and actual `predicted_n=1`, retains that sampled token, and requires
`prompt_n=N`, `cache_n=0` and `n_saved=N`. It never labels this operation as zero
generated tokens. Use fresh state basenames to avoid replacing an earlier server
state file; the measurement helper cannot inspect the server's filesystem.

Decode requires `n_restored=N`, submits the full original prompt with
`cache_prompt=true`, and accepts only `cache_n >= N-1`, `prompt_n <= 1` and the
requested generation count. It records restore wall time, streamed decode TTFT,
restore-to-first-token time and combined restore/decode wall time. A re-prefill
or incomplete restoration fails instead of being reported as a successful
handoff. For multiple repetitions the helper generates matching basenames such
as `trial-001.state`, `trial-002.state` and `trial-003.state` on both actions.
Transfer every corresponding file before running the decoder repetitions.

These slot files and the existing `kv_file.py` transfer path stage KV bytes in
host memory; they do not establish direct CUDA/Vulkan device-buffer handoff.
The helper does not time or perform the interhost transfer, so its stage totals
must not be presented as independently measured end-to-end distributed request
latency. Compare generated tokens and account for state-transfer time separately.

Every action requires a **new** `--output` JSON path whose parent exists; an
existing file or symlink is refused before any HTTP work. The file is created
with mode 0600, checkpoints retain completed trials, and failures keep available
events and an incomplete SSE tail. Results include prompts, server response data
and generated text, so keep them private and review them before publication.
The console prints only the action's pass/fail marker. No HTTP redirects or
environment proxy configuration are followed.

`--timeout` bounds each HTTP exchange with a socket timeout and watchdog;
`--max-response-bytes` and `--max-total-response-bytes` bound response capture.
A malformed/truncated stream, missing final result, bad token/cache count,
non-finite JSON, capture limit or HTTP error makes the action fail. An incomplete
capture is explicitly marked and cannot pass. These checks cover execution and
measurement integrity, not semantic answer quality or hardware correctness.

Run the portable helper's loopback fake-server tests without loading a model:

```sh
python3 -B -m unittest discover -s integrations/llamacpp -p 'test_measure_inference.py' -v
```
